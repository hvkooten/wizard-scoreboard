ISSUE (RESOLVED): App crashed on Android launch
=======================================================================
Symptom: Android.Runtime.JavaProxyThrowable on startup (Android only; never
reproduced on the Windows head).

Root cause (confirmed from device logcat provided by the human):
  System.NullReferenceException: "The current Activity cannot be detected."
    Microsoft.Maui.Devices.DeviceDisplayImplementation.GetKeepScreenOn()
    -> ScreenWakeService.SetKeepScreenOn()
    -> ScreenWakeService.Apply() -> ReleaseKeepAwake()
    -> ScoreBoardPage.RefreshUI()
    -> ScoreBoardPage..ctor()      (built by DI during app startup)

  ScoreBoardPage is resolved by the DI container at startup. Its constructor calls
  RefreshUI() -> ReleaseKeepAwake() -> DeviceDisplay.Current.KeepScreenOn. On Android
  that API needs the current Activity, which is not ready that early, so it throws and
  the NRE crosses JNI as JavaProxyThrowable -> hard crash.

FIX (implemented):
  src/scoreboard/Services/ScreenWakeService.cs -> SetKeepScreenOn() is now fail-safe:
  keeping the screen on is best-effort UX, so it swallows NullReferenceException /
  InvalidOperationException when the Activity is not ready. It self-heals: OnAppearing()
  /RefreshUI() run again once the Activity is live and apply the real state.
  Build: solution builds successfully (Windows + Android heads, 0 errors/warnings).

Diagnostics kept as a safety net:
  src/scoreboard/Platforms/Android/MainActivity.cs logs the full managed inner-exception
  chain and unwraps JavaProxyThrowable (Java type/message/stack), chunked to avoid logcat
  truncation, and also persists each report to files/crashlogs for offline pull.
